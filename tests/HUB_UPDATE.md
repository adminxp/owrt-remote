# Обновление панели из Hub (v118)

Перед «Поиск роутеров» владелец видит кнопку «Обновление панели».
Обе кнопки оформлены как остальные элементы шапки и стоят рядом на ПК.
На мобильных устройствах каждая занимает отдельную строку.
Подтверждённая актуальная сборка обозначается зелёным, доступное обновление —
жёлтым. Проверка и ошибка проверки остаются нейтральными. Сообщение проверки
размещено первым блоком панели над шапкой, выровнено по центру и отделено
от элементов управления отступом. Во всех состояниях текст блока белый,
рамка полупрозрачная, как у «Открыть группы роутеров», фон прозрачный. Ширина ограничена
680 пикселями, на ПК сверху добавлен отступ 12 пикселей. На мобильном длинный
текст переносится без обрезки. Элементы шапки идут последовательно:
ЦП / ОЗУ / ДИСК, обновление панели, эффекты, поиск роутеров. Кнопки занимают
отдельные строки одинаковой ширины, включая горизонтальную ориентацию.
Мобильная кнопка «Поиск роутеров» имеет такую же фиолетовую заливку и белый
текст, как «Эффекты», в том числе при открытом поиске.
Между мобильными кнопками обновления, эффектов, поиска, меню Hub, добавления,
групп и статистики используется единый интервал 8 пикселей. Раскрытые блоки
отделены тем же интервалом; скрытые элементы не оставляют пустых промежутков.

При открытии панели запускается общая фоновая проверка исходного файла Hub.
Проверки кешируются на 5 минут; открытые видимые вкладки опрашивают результат
раз в минуту. Нажатие кнопки позволяет запросить проверку раньше, с ограничением
не чаще одного сетевого запроса за 15 секунд. Во время установки статус
запрашивается раз в 2 секунды. Скрытые вкладки приостанавливают опрос.

Сравнивается SHA-256 файла, поэтому изменения обнаруживаются и при неизменной
версии v118. «Доступно обновление» означает, что опубликованный файл отличается
от запущенного. Установка требует подтверждения конкретной проверенной сборки.
Ветка GitHub использует свой `RAW_REPO_BASE`; при переносе в GitVerse необходимо
сохранить его собственный `RAW_REPO_BASE`. Адрес не принимается от браузера.

Обновляется только файл VPS-панели. Процесс запускается отдельной transient-службой
systemd, сохраняет резервную копию, проверяет размер, UTF-8, синтаксис Python
и совместимость обновления, затем атомарно заменяет файл. Проверка `/health`
подтверждает именно SHA-256 новой запущенной сборки. При ошибке после замены
возвращается предыдущий файл и повторно запускается Hub. Результат сохраняется
в `STATE_DIR/panel-update/job.json`; предыдущий файл — `previous.py` рядом.
После успеха страница автоматически перезагружается один раз.
После перезагрузки сообщение завершённой задачи больше не обещает повторную
перезагрузку: при подтверждённой актуальности выводится «У вас последняя версия
панели, обновление не требуется». Следующие проверки и доступные новые сборки
показывают текущее состояние, даже если сохранена предыдущая успешная задача.

Очередь, состояние и резервная копия ограничены одним обновлением. Блокировка
flock не позволяет запустить две установки; при аварии её освобождает ядро.
Зависшая или прерванная задача получает явный неподтверждённый результат.
API доступен только владельцу, POST требует CSRF-токен и проверку Origin.

Подтверждение установки открывается встроенным адаптивным баннером панели с
версией, контрольной суммой, источником и кнопками «Отмена» и «Обновить».
На мобильном он занимает ширину экрана с безопасными полями, не вызывает
системное белое окно браузера и не допускает горизонтального переполнения.

До публикации этой функции публичный старый Hub может не поддерживать проверку
сборки после перезапуска. Такая сборка отклоняется до замены файла.
Сообщение «Сборка в источнике ещё не поддерживает проверяемое обновление из
панели» означает отсутствие механизма обновления в загруженном файле, а не
отсутствие новых изменений. При такой ошибке кнопка остаётся нейтральной:
актуальность установленной сборки не подтверждена.

## Проверка через кнопку без публикации

Скрипт ниже подготавливает на VPS две временные сборки из текущего локального
исходника v118. Различается только тестовая отметка, поэтому их SHA-256 разные.
Первая сборка устанавливается скриптом, вторая предлагается кнопкой обновления.
Только эти временные сборки читают файл-кандидат на самой VPS вместо GitHub.
Ссылки установки и `RAW_REPO_BASE` остаются прежними. Данные обычной очереди
обновления и её резервная копия сохраняются: тест использует отдельный каталог.

Подготовить тест из Windows 11 PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\test-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Prepare
```

Для повторного теста вместо двух отдельных команд `Restore` и `Prepare`
используется одна команда. Она возвращает прежний файл, если тест уже был
подготовлен, затем устанавливает новые тестовые сборки. При ошибке возврата
второй шаг не выполняется; исходная резервная копия не перезаписывается.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\test-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Retest
```

После `SELF_UPDATE_LOCAL_TEST_READY`:

1. Открыть панель владельцем, нажать Ctrl+F5 и дождаться жёлтой кнопки
   «Обновление панели».
2. Нажать кнопку и подтвердить установку. Источник в подтверждении —
   «Локальный тест на VPS (без GitHub)».
3. Дождаться результата и автоматической перезагрузки страницы. При успехе
   кнопка станет зелёной.

Это настоящая замена файла Hub и перезапуск `owrt-remote` через systemd.
Сервис кратковременно перезапускается; скачивание с GitHub этим тестом
не проверяется. Подготовка также перезапускает Hub. При неудаче подготовки
скрипт возвращает исходный файл и проверяет работоспособность.

Проверить установленный файл, результат задачи, активность службы и SHA-256
запущенной через `/health` сборки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\test-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Status
```

Успешный итог — `SELF_UPDATE_LOCAL_TEST_PASSED`.
`SELF_UPDATE_LOCAL_TEST_WAITING` означает, что успех ещё не подтверждён;
следом выводятся статус задачи и результаты проверки.
`SELF_UPDATE_LOCAL_TEST_NOT_PREPARED` означает, что каталог теста отсутствует.
Диагностика показывает `installed_build` (`baseline`, `candidate` или `other`),
контрольные суммы установленного и реально запущенного файла, а также
`running_installed_file`. Она не меняет VPS и не показывает ключи. Если сборка
теста реально запущена, но браузер сообщает об ошибке проверки GitHub, нужно
сверить VPS, на которую указывает открытый домен, и полный результат подготовки.

После проверки вернуть файл, который работал до подготовки теста:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\test-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Restore
```

Ожидается `SELF_UPDATE_LOCAL_TEST_RESTORED`. Скрипт проверяет резервную копию
`/opt/owrt-remote/self-update-local-test/before.py`, возвращает её, перезапускает
Hub, проверяет `/health`, затем удаляет только созданные файлы теста.
Повторная подготовка не перезаписывает существующую резервную копию: сначала
нужно завершить тест и выполнить `Restore` либо использовать `Retest`.
После восстановления обычная
проверка снова использует GitHub; до публикации совместимой сборки исходное
сообщение о неподдерживаемом обновлении ожидаемо появится снова.

## Локальная установка с Windows 11

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Install
```

После `HUB_SELF_UPDATE_V118_Install_OK` обновить страницу через Ctrl+F5.

Откат локальной установки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-hub-self-update.ps1" -Vps "root@193.233.82.38" -Action Rollback
```

Используется резервная копия
`/opt/owrt-remote/owrt-remote-hub.py.bak-before-hub-self-update-v118`.

## Проверки

```powershell
python tests/test_hub_update.py -v
python tests/test_hub_self_update_local.py -v
node tests/test_hub_update_ui.cjs
```

Python проверяет загрузку из правильного источника, ошибки сети и синтаксиса,
неизменную версию, проверку контрольной суммы, сохранение рабочего файла,
установку и откат, восстановление состояния после перезапуска и права API.
Перезапуск systemd и ответы health в этих тестах моделируются.
Отдельный тест локального сценария проверяет реальные файлы и HTTP `/health`
до и после повторного запуска сервера с новым исходником, успешное обновление,
возврат исходного файла, сохранение обычного состояния обновления и подготовку
UTF-8 файлов из Windows PowerShell. Команды systemd в автоматическом тесте
моделируются; их выполнение на VPS проверяется ручным сценарием выше.
Браузер проверяет размеры 1280, 980, 320, 390, 430, 844 и 932 пикселя,
положение статуса над шапкой, перенос текста, размеры мобильных кнопок,
подтверждение/отмену,
разрыв связи при перезапуске, результат и отсутствие повторной установки
или цикла перезагрузок страницы. Сам VPS этими тестами не изменяется.
